# Roadmap

Athar is a v0.1 scaffold. Everything documented elsewhere on this site is implemented and working; this page is the honest list of what isn't yet — plus, below, what's built and merged but not in a release you can download yet.

## On main, not yet released

- **Heatmap-over-page-capture underlay.** The click heatmap now draws its density field over a real picture of the page when one exists, instead of only the wireframe schematic. This is **operator-supplied upload, not automatic capture**: an editor or owner uploads a full-page PNG/JPEG of their own page through the dashboard, keyed to one page and one viewport width — the tracker did not change to add this, and still records only a click's position, viewport size and a CSS selector, never page content. See [Heatmaps](./heatmaps.md#page-captures), [Privacy](./privacy.md#page-captures-an-operators-own-choice-not-the-trackers) and [API](./api.md#page-captures). Without a matching capture, the view falls back to the wireframe, badged as a schematic — this is the default for every page and viewport nobody has captured yet, and always the case for "All viewports". This has landed on `main` and is covered by tests, but it is not part of the 0.1.0 release — see [Changelog](./changelog.md).

## Planned, not yet built

- **PWA reinstatement — installability, without the offline machinery.** The dashboard shipped an installable PWA (`manifest.webmanifest`, a service worker, app icons) at v0.1.0; it was removed when the dashboard was rewritten from React to hand-written HTML/CSS/JS (see [Changelog](./changelog.md)), because the service worker's offline cache and update handling was real, ongoing complexity for a dashboard that is otherwise build-free. The plan is to bring back the manifest and icons (installability, cheap); the service worker (offline support) stays out unless a concrete case for it shows up — the dashboard's whole purpose is showing live server state, and an offline copy of that is a stale copy. Until this lands, the dashboard is a plain web page: no home-screen install, no offline access.
- **Two-factor authentication (TOTP).** The schema already has a slot for a TOTP secret per user (`store.User.TOTPSecret`), and the public user shape already reports whether one is enrolled — but the enrollment flow and the login-time challenge are not built. Right now that field is always empty and login is password-only.
- **Session insight (rrweb).** This is a different feature from the page-capture heatmap underlay above: an operator uploading a picture of their own page is a manual, occasional, human action with no tracker change involved. Session insight would mean the tracker itself automatically recording a visitor's DOM — a deliberately separate, clearly-scoped capability, not an extension of today's coordinate-only heatmap sampler. It would need a snapshot mechanism, and the plan is to build that on [rrweb](https://github.com/rrweb-io/rrweb) (MIT), strictly opt-in and shipped as a separate module rather than added to the 1.6 KB default tracker. The cookieless/no-DOM-capture path described in [Privacy](./privacy.md) stays the default either way: today's tracker collects no DOM content, and the page-capture underlay above doesn't change that — it adds an operator-uploaded image, not tracker-side capture.
- **Funnels UI.** The data to build funnels from (custom events with properties, pageviews with paths) is already collected; there's no funnel-definition or visualization surface in the dashboard yet.
- **Website settings UI.** Minting or revoking a share link (`POST /api/websites/{id}/share`) and deleting a website (`DELETE /api/websites/{id}`) are implemented and enforced server-side — see [API](./api.md#websites) — but the dashboard has no screen for either yet. Both are API-only today, so a revocable share link is something you currently mint with a request, not a toggle.
- **Account & user administration UI.** Same shape: changing your own password (`POST /api/me/password`) and the admin user CRUD (`GET`/`POST /api/users`, `DELETE /api/users/{id}`) are implemented, authenticated and tested, with no dashboard screen driving them yet.
- **Teams UI.** Per-website roles (owner/editor/viewer) exist and are enforced by the API today — see [API](./api.md#websites) — but there's no dashboard screen yet for inviting a teammate to a specific website; grants are currently a backend capability without a frontend for managing them.
- **Packaged distribution.** No Docker image, no downloadable release binary yet — [Install](./install.md) is build-from-source only.

## Also worth knowing

- Revenue reporting is totals-per-currency over a time range today (see [Ecommerce](./ecommerce.md)) — no product/SKU breakdown, no cart funnel.
- GeoIP data (`.mmdb`) is not bundled and must be supplied by the operator — see [Self-hosting](./self-hosting.md#geoip).

If a feature isn't listed as implemented on the [Getting started](./getting-started.md), [Tracker script](./tracker.md), [Heatmaps](./heatmaps.md), [Ecommerce](./ecommerce.md), [Privacy](./privacy.md), or [API](./api.md) pages, treat it as not built yet rather than assuming it's just undocumented.
